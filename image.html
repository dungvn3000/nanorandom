How it works. Your image is read as raw bytes and fed into PBKDF2-HMAC-SHA-256 (200 000 iterations) with the following inputs:
• key material — image_bytes ++ utf8(passphrase) ++ word_count_byte
• salt — SHA-256 of the image bytes (ties the KDF to this exact file)
The derived bits are truncated to the BIP39 entropy length (128–256 bits), a standard BIP39 checksum is appended, and the result is mapped to words from the official 2048-word English list. The high iteration count makes brute-forcing the image or passphrase ~200 000× harder than a plain SHA-256 hash. Deterministic: the same image + same passphrase + same word count always produce the same seed. That is exactly what makes the image a usable backup — re-open this page, pick the same file, type the same passphrase, and the seed is regenerated.

The image is the secret. Anyone who obtains your exact image file (and your passphrase, if you set one) can reproduce this seed. Keep the file private, offline, and ideally unpredictable — not a famous public photo someone could try. Keep the exact bytes. Re-saving, re-encoding, compressing, cropping or even stripping metadata changes the bytes and produces a different seed. Store the original file untouched. The SHA-256 fingerprint above lets you verify you picked the right file when restoring.

Use a passphrase. With a strong passphrase, an attacker who finds your image still cannot recover the seed without it. Treat it like a BIP39 passphrase (“25th word”): memorise it, do not store it next to the image. Losing either the image or the passphrase means the seed is unrecoverable.

Need a one-time random seed instead? Use the standard BIP39 generator — it draws fresh CSPRNG entropy each time and is not reproducible. This image tool is for reproducible, image-backed seeds.
