Decentralization Password Generator — independent CSPRNG, no derivation

Each character is drawn uniformly using rejection sampling (bytes in the modulo-bias zone are discarded and redrawn). By default the stream is a direct crypto.getRandomValues() source (fully offline). With "Mix live Nano blockhashes" enabled, characters are drawn from a SHA-256 counter-mode stream seeded with a fresh 32-byte CSPRNG salt plus up to 16 validated live Nano blockhashes per Generate; the password then depends on the fresh salt — it is not reproducible from any previous salt or block set. At least one character from each enabled set is guaranteed; a Fisher-Yates shuffle (using the same CSPRNG stream) then randomises all positions uniformly so no slot reveals which charset it came from.

Why mix live Nano blockhashes? Browser CSPRNG is a single point of failure — a buggy or mocked browser RNG alone would make the output fully reproducible. With the stream additionally seeded by public, timestamped block windows, an attacker must also know which window your Generate drew from. It adds no theoretical entropy, but one broken RNG implementation can no longer collapse the password.
