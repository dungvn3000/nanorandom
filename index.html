Why Nano?

Nano (XNO) is a feeless, eco-friendly cryptocurrency with a unique block-lattice architecture. It is perfectly suited as a live entropy source for this tool:

Blocks confirmed continuously Nano settles transactions — on average one or more per second, and free — so fresh blockhashes keep arriving 24/7. We never run out of new randomness.
256-bit blockhashes Each Nano block has a 256-bit cryptographic block hash that no one predicted beforehand. The hash is public auxiliary input and is not treated as a secret.
Publicly verifiable Any hash you see in this app links straight to nanexplorer.com. The displayed hash can be checked against an explorer, but this application does not independently verify Nano consensus or confirmation status.
Green & feeless No mining, no wasted energy, no cost per block. The "noise" of real user transactions keeps the pipeline running without contributing to carbon or network congestion.
But remember: public blockhashes alone are not secret. The system salt (256-bit, auto-generated client-side) keeps each seed private; the user salt you type adds a second, personal layer.
Why NanoRandom? — Lessons from the 2026 Coldcard RNG flaw

In July 2026, Coinkite's official advisory disclosed that a firmware integration error had routed Coldcard seed generation to a deterministic software PRNG instead of the hardware RNG since March 2021 (effective entropy ≈ 40 bits on Mk3, ≈ 72 bits on Mk4/Mk5/Q, versus the expected 128). On July 30, 2026, Galaxy Research mapped a sweep of 1,196 addresses and 1,082.65 BTC (~ $70.2M) in 41 minutes and linked the pattern to this flaw (suspected, based on on-chain analysis — later suspected waves raised the estimate to ~ 1,367 BTC).

Single point of failure The devices trusted a single onboard RNG. A macro check (#ifdef vs value check) silently bound seed generation to a fallback PRNG seeded from the chip UID and timer registers — for four years, with no visible error.
NanoRandom mixes 2+ independent sources Your seed is a hash of auto system salt (browser CSPRNG) + optional user salt (your text) + live Nano blockhashes (verifiable, outside world). The browser CSPRNG is the primary secret entropy source; Nano blockhashes are public auxiliary input, and the optional user input only adds meaningful protection when it is independently unpredictable.
Open code, open math Blockhashes link straight to nanexplorer.com. The full formula is written on this page, and the whole app is a single auditable HTML file you can save and run offline.
The browser random value is the secret part As Coinkite's own advisory said, extra protection (dice / passphrase) only helps when it is unpredictable. Same principle here: the blockhash is public; the browser-generated random value is the primary secret input, and a user-provided value adds protection only if it is high entropy and kept private.
The lesson is: never trust one RNG alone. Note also that an online JavaScript app still relies on its own trust chain — the hosting server, DNS/TLS, your browser and OS, browser extensions, CDN libraries and the explorer API. For significant funds, prefer a saved, offline copy of this page on a trusted device.

Frequently Asked Questions
1. What is a BIP39 mnemonic seed phrase?

BIP39 is the standard used by Nano, Bitcoin and many other cryptos to represent a private key as a list of human-readable words (12 / 15 / 18 / 24). The words come from a fixed dictionary of 2048 entries, so the phrase can be written down and retyped safely.

2. Where does the randomness come from?

Three sources are combined and SHA-256 hashed:

  • System salt – 32 raw CSPRNG bytes from your browser's crypto.getRandomValues() on page load, fed to SHA-256 as-is (the hex string shown in the UI is display-only). Auto-generated, readonly, regenerable with .
  • User salt – optional text you type yourself, encoded as UTF-8 bytes. Leave empty unless you want a second, personal layer.
  • Live Nano blockhashes – fetched from api.nanexplorer.com/last-blocks every 3 seconds; up to the last 16 hashes (rolling buffer), each 64-hex value decoded to its raw 32-byte form.

Result: entropy = SHA-256( rawSystemSaltBytes ++ utf8(userSalt) ++ blockhashBytes )[0 : ENT/8]

3. Why mix blockhash with two salts?

Blockhashes are public. A blockhash alone is not a private secret. The system salt is auto-generated by your browser (so nobody can calculate it in advance), and the user salt adds a second layer that you control — if an attacker knew the blockhash(es) and guessed one of the salts, they still have to guess the other. On the Nano network, both salts stay local, never uploaded.

4. Is this tool safe? Where is my seed stored?

Seed derivation runs locally in your browser — no seed, salt, entropy or user-entered text is intentionally transmitted by the application. The page still downloads web assets (e.g. CDN libraries) and fetches public blockhash data over the network. Before holding real funds, consider using a trusted offline/air-gapped device to sign transactions.

5. Why do 12 / 15 / 18 / 24 word options exist?

BIP39 requires the entropy length to be a multiple of 32 bits. The supported lengths are:

  • 12 words → 128 bits entropy + 4-bit checksum
  • 15 words → 160 bits entropy + 5-bit checksum
  • 18 words → 192 bits entropy + 6-bit checksum
  • 24 words → 256 bits entropy + 8-bit checksum
6. Can I reuse a salt later?

The salt is part of your entropy. If you regenerate the same salt (e.g. by saving it) combined with the same blockhash, you'd get the same seed. In practice the blockhash changes every few seconds, so each run is unique. If you want to back up a seed, use Download instead.

7. What happens if the API is down?

The badge switches to API Off, the blockhash buffer stays as-is and the seed will not regenerate until the connection recovers (auto-retry on every poll). You can keep editing the salt to regenerate the seed from the existing buffer.

Security tips
  • Write down your seed phrase on paper and store it offline. Never store it in cloud notes or screenshots.
  • Never share the seed or the salts (system + user) with anyone. Anyone with both salts + the matching blockhash window AND the exact derivation details (version, hash order, block order, word count, encoding) can fully recover your wallet.
  • For significant funds, prefer using an offline/air-gapped device and verify the seed derivation there before trusting any on-screen values.
  • This tool is open and client-side — you can save the page and run it offline after the first load.
