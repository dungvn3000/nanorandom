The Problem

A single RNG is a single point of failure

Most tools rely on one source of randomness. That’s fine — until it isn’t.

💻

Browser CSPRNG alone

crypto.getRandomValues() is excellent, but it is the only gate between you and a broken RNG. A buggy browser build, a mocked environment, or a compromised test harness silently collapses your key’s entropy to zero.

💸

Hardware RNG devices are expensive

True random number generators (HSMs, YubiKeys, Ledger, dedicated TRNG boards) provide excellent physical entropy — but they cost money, require drivers, and are not available to most people when they need to generate a wallet today.

🦰

Hardware RNG can still be buggy or backdoored

Even certified hardware is not immune. The Coldcard Mk1–Mk3 hardware wallet used an ATECC508A secure-element chip whose on-chip TRNG output was found to be potentially biased — Coldcard responded by XOR-ing the chip’s output with a software PRNG as a defensive measure. The Intel RDRAND instruction shipped a bug (fixed in 2019) that made it return 0xFFFFFFFF on certain CPUs. The NSA’s Dual_EC_DRBG standard contained a deliberate backdoor. Supply-chain attacks can replace a legitimate TRNG chip with one that generates predictable output. Hardware is not a guarantee; diversity of sources is.

🕵️

Closed-source online tools

Many wallet generators run on a server you cannot inspect. You have to trust that the server’s RNG is honest and that your generated keys are not logged. That trust is unverifiable.

🔄

Reproducible outputs

If an attacker knows (or can predict) your RNG state — through a VM snapshot, a leaked seed, or a deterministic test environment — every key you generate from that point forward is compromised.

The Solution

Two independent entropy sources, hashed together

NanoRandom layers your browser’s CSPRNG on top of live, public Nano blockchain hashes. Both must be broken simultaneously for the output to be predictable.

An attacker who compromises your browser RNG still cannot reproduce your output without also knowing exactly which blocks were fetched at the moment you clicked Generate — a moving, public target that changes every few milliseconds on the Nano network.

An attacker who controls the entire Nano network still cannot predict your output without your browser’s secret 32-byte CSPRNG salt.

1

System CSPRNG — the secret anchor

crypto.getRandomValues(32 bytes) — OS-backed, never leaves your device, never exposed.

2

Live blockchain hashes — the public witness

Up to 16 validated Nano blockhashes fetched at generate-time. Public and timestamped, verifiable by anyone.

3

SHA-256 combiner — one-way mix

Both inputs are concatenated and hashed. Neither input can be recovered from the output.

entropy-formula.txt 
# Inputs
salt    = crypto.getRandomValues(32)
            # fresh CSPRNG bytes, secret, per-click

userSalt = UTF-8(user_text)
            # optional extra passphrase

blocks  = validated_nano_hashes(≤16)
            # 64 hex chars each → 32 raw bytes
            # fetched live, deduped, hex-validated

# Mix
combined = salt ++ userSalt ++ blocks

# Output entropy (BIP39 uses 16–32 bytes)
entropy  = SHA-256(combined)[0 : ENT_bytes]

# Both must be broken to predict entropy:
#   compromised CSPRNG  → blocks protect it
#   controlled network  → CSPRNG salt protects it

Offline-first. With "Mix blockhashes" disabled, the tool generates entropy purely from crypto.getRandomValues() — the same method used by major hardware wallets and browser extensions. No network call is ever required.

Why blockchain?

A free, public, tamper-evident entropy source

Live blockchain hashes act as a publicly-verifiable entropy witness that costs nothing to use and is controlled by no single party.

📶

Always available, always free

Public blockchain APIs require no account, no API key, and no payment. Any connected device can query them in milliseconds.

📋

Publicly verifiable

Every blockhash used in your generation is displayed and linkable. A third party can verify the hash existed at that moment in history.

⏱️

Timestamped & ephemeral

Blocks are confirmed once and are immutable. The exact set of hashes available in a 2.5-second window is practically impossible to predict in advance or replay.

🚫

No single controller

No single entity can silently bias or predict all Nano block hashes without owning the majority of the network — a public, detectable attack.

🔒

Defense-in-depth

Even if the blockchain data were biased or manipulated, the secret CSPRNG salt — which never leaves your device — makes the final entropy unpredictable to the attacker.

💰

Replaces expensive hardware

Hardware TRNGs provide physical entropy isolation. Blockchain mixing provides a free software-level equivalent: an entropy source outside your local machine that an attacker must also compromise.

Why Nano blockchain?

High-frequency, feeless blocks — ideal entropy variety

Not all blockchains are equally suited as entropy witnesses. Nano’s architecture makes it uniquely well-suited for this purpose.

Same approach, any blockchain. The mixing technique works with any chain that exposes a public block-hash API — Ethereum, Bitcoin, Solana, etc. NanoRandom uses Nano because its feeless model produces a very high volume of unique hashes per second, maximising the variety of entropy windows available to each generation event. Swapping the API endpoint would work identically.

Security properties

What this tool guarantees — and what it doesn’t

✅ What NanoRandom guarantees

  • ✔ Entropy never derived from Math.random() — always from crypto.getRandomValues().
  • ✔ Fail-closed: if crypto.subtle or getRandomValues is unavailable, generation refuses to proceed rather than silently degrading.
  • ✔ Blockhash validation: each hash must be exactly 64 uppercase hex characters before it is accepted into the mix.
  • ✔ No XSS surface: all DOM writes use textContent or createElement — never innerHTML for user-controlled data.
  • ✔ Rejection sampling for all character/index selection — zero modulo bias.
  • ✔ Correct BIP39 checksum (ENT/32 bits of SHA-256).

⚠️ What this tool does not guarantee

  • ⚠️ Protection against a fully compromised operating system or browser process. If your OS is rooted, no software tool helps.
  • ⚠️ The nanexplorer.com API is a third-party service. If it is down or returns invalid data, block mixing falls back to CSPRNG-only (or throws, depending on mode).
  • ⚠️ Screen privacy: the seed phrase is displayed in plaintext. Use in a private location, enable browser privacy mode, and clear the page after writing down your phrase.
  • ⚠️ Long-term storage security. The tool generates the phrase; storing it safely on paper, metal, or an encrypted vault is your responsibility.
